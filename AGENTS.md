## Learned User Preferences
- GRID_API_KEY (Axword) is pro-series only: never search/download/cache scrims, practice games, tryouts, or private scrim feeds; no override flag. Enforce via `scripts/grid_api.py` + `.cursor/rules/grid-api-pro-only.mdc`.
- Prefer maximum native timeline granularity for game replays; do not downsample frames just to shrink JSON when positioning fidelity matters. Prefer fast ROFL→JSONL ingest as a core workflow (offline/packet-driven when quality gates hold) over multi-tens-of-minutes Replay API capture; ROFL tooling should run on macOS and Windows.
- Prefer combat/team-win results shown visually (who wins / strength bands), not only raw damage numbers; treat pBlue/pRed as heuristic model scores (“model edge”), never as calibrated win probabilities or odds %.
- Map → calculator flow should support multi-champion NvM selection, including selecting both teams at once.
- Map review should support zoom/pan and show turrets, inhibitors, nexus, and jungle camps with official LoL wiki icons, clear alive/dead availability at second precision, and larger structure/camp icons than champion markers; fog of war should distinguish unseen-by-anyone vs unseen-by-opponents, and vision presence should inform skillshot xH.
- Dead champions must be excluded from calculator imports (do not count their combat stats); missing HP/combat/career fields from replay sources must stay unknown rather than faked as dead/full/zero; never fixture-remap another match’s HP/combat/ranks onto a real match; gate Send on selected units’ per-frame `hpKnown`/`combatStatsKnown`/`abilityRanksKnown` (match-level `calculatorReady` may stay false when early same-match HP density is honestly incomplete); legitimate early liveclient score zeros are fine when the source marks them known.
- Action timelines must respect remaining HP via realistic survival/CD/cast/death timing — never absolute HP% bands that ban ability slots or cliff auto counts (low HP is not “one AA max”); a fighter who would die mid-window still cannot complete post-lethal actions.
- Prefer a competitive-style map scoreboard (towers, gold with delta, kills, role quests, grubs, dragons, baron, elder) and include objective buffs in combat math; grub-touch estimates must be auditable (assumptions, burn uptime, tick rate, melee/ranged, plate-equivalent) so numbers are reproducible—prefer mining high-confidence proxies (including match VOD analysis) when confidence is low.
- Do not use Obsidian vault or recall for this workspace; project context lives in-repo (docs/, AGENTS.md, code).
- Prefer dark Anthropic/Apple-like product-tool UI that feels integrated, not a collage of disconnected assets; avoid em dashes in user-visible copy; during long overnight research runs prefer plain one-liner progress status over jargon-heavy updates.
- Prefer extended-fight modeling with resource regeneration, calibrated against actual match kill windows from the timeline (≥3 cross-checks per game when available); use sqrt-time bin HP-error variance as a phase diagnostic for compounding returns, not a single coefficient to fit; when early and late tracks both fire, investigate opener vs finish separately and never one coefficient for both; holdout before claiming a fix; research classes like `false_all_in` / `early_poisoned` stay diagnostics only—they do not mark the calculator calibrated; during kill-window autoresearch auto-pick the next hypothesis from `docs/rofl-research/autoresearch/program.md` (never ask the human to choose tracks); product kill-window defaults must use non-drop mark selection (`cusum_engage_then_skills` / `post_engage_killer_skills`)—`near_hp_drop` is research-only; research `shipGate` / product `productShipGate` / `actionReplayGate` (actionCoverage F1) / research `packetDecodeGate` / product `calculatorReadyGate` / research `fightOutcomeGate` / `digestCleanGate` are not calibrated win odds—`calculatorReadyGate` means honest same-match HP+combat+ranks Send (+ AA timeline), not VOD fight match; `fightOutcomeGate` is the separate ~95% fightAgreement goal (unfreeze of composite 0.9683 allowed only under that metric law); reject zero-damage log-echo as gate evidence; packet decode alone is not enough—pursue the full product path (same-match HP+combat+ranks, Send, AA timeline in product UI); overnight autoresearch Task/subagents use Auto when the human says Auto (overrides GOAL model pins).
- Champion-history board should separate AS from AH, show gold as total/items/bag when known, quantify cumulative dragon-buff effects (MS, damage amp, mitigation), and order columns by win-correlation at the current game time; partial liveclient rows may show K/D/A, total CS, and vision while marking unsupported damage/gold/objectives unavailable—never synthesize zeros or treat partial coverage as full career.

- Full game knowledge is ingested via `npm run ingest:lolwiki` into `public/data/lolwiki/` (all Summoner's Rift items only — not TFT/Arena/ARAM, all runes including Unsealed Spellbook, all summoners, all 171 Meraki champion kits). Do not ship a hand-curated subset as the source of truth.
- This repo is a LoL combat strength analysis app (React + TypeScript + Vite) with a phased roadmap: v1 isolated 1v1 calculator → v2 map/game-state import into the calculator → v3 xH/xHm → v4 teamfight win-odds ranges (worst/typical/best).
- xH is skillshot hit chance from similar historic situations (mobility buckets, map zones, only when enemies are in ability range); xHm is multi-target hit distribution; target-side objective-resolved mobility (e.g. Cloud Soul MS) must reach every xH path; CC that lands should raise follow-up skillshot xH inside the crowd-control window, and kiting/spacing plus engage/engage-success are the intended modeling horizon after standoff 1v1 (Axword); current code uses priors until historic rates replace them.
